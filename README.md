# MoonTranslate — แปลเกมและมังงะบนเครื่อง

รุ่นทดลองสำหรับ Windows 11: อ่านข้อความอังกฤษ/ญี่ปุ่นจากพื้นที่บนจอหลัก แปลเป็นไทย และวาดคำแปลทับตำแหน่งเดิมโดยอัตโนมัติ เหมาะกับบทสนทนา Visual Novel และการอ่าน MangaDex ในเบราว์เซอร์

## อัปเดตตามต้นแบบ local-game-subs 1.0.0

ปรับหน้าตาและการวางซับโดยอ้างอิงไฟล์ ZIP ที่ผู้ใช้ให้มา ยังคง RapidOCR และ Qwen3 4B Instruct เดิม ตามขอบเขตที่เลือกไว้

- ตัวอย่างซับใช้ตัววาดเดียวกับ overlay ปรับฟอนต์ สี ขนาด เส้นขอบ และความทึบแล้วเห็นผลทันที
- เลือกฟอนต์ภาษาไทยจากเครื่อง พร้อมสีข้อความสำเร็จรูปหรือเลือกสีเอง
- โหมดเกมเลือกกล่องพอดีกับประโยคได้ ส่วนมังงะยังจำกัดตามพื้นที่ข้อความเดิม ไม่ขยายออกไปด้านข้าง
- จำค่าหน้าตาเมื่อปิดแอป แล้วคืนค่าเมื่อเปิดใหม่ ในไฟล์ appearance.json ของแอป
- ปุ่มเลือกพื้นที่ เริ่ม/พัก และสถานะอยู่ด้านล่างเสมอ ส่วนการตั้งค่าเลื่อนได้
- ตัวเลือกพื้นที่: ลากนอกกรอบเพื่อวาดใหม่ ลากในกรอบเพื่อย้าย ปุ่มลูกศรขยับ 1 จุด Shift+ลูกศรขยับ 10 จุด C จัดกลางจอ และ **Enter เพื่อยืนยัน**; Esc ยกเลิก

ต้นแบบ: local-game-subs โดย Ashiran Arayachon (2026), MIT; เก็บข้อความใบอนุญาตไว้ใน REFERENCE-LICENSE.txt การปรับนี้นำแนวทางส่วนติดต่อและการวางซับมาประยุกต์ ไม่ได้ย้ายมาใช้ตัวรันโมเดลภาพของต้นแบบ

ทดสอบการไม่ล้นกรอบมังงะ กล่องพอดีข้อความ การขยับ/ยืนยันกรอบ และการบันทึก/คืนค่าหน้าตาด้วย test_appearance.py แล้ว

## เริ่มใช้งานบนเครื่องนี้

ติดตั้ง Python, OCR, ตัวรัน Ollama และโมเดล qwen3:4b-instruct แล้ว เปิด **Start.cmd** ได้เลย ไม่ต้องติดตั้งซ้ำ

1. เปิดเกมแบบ **Windowed / Borderless** หรือเปิดหน้าอ่านบน MangaDex และใช้จอหลัก
2. เปิด `Start.cmd` รอข้อความ “พร้อมใช้งาน”
3. เลือกโหมดเกมหรือมังงะ และภาษาต้นฉบับ
4. กด **เลือกพื้นที่บนจอหลัก** แล้วลากครอบบริเวณข้อความ ปรับตำแหน่งแล้วกด **Enter** เพื่อยืนยัน
5. กด **เริ่มแปลอัตโนมัติ** แล้วกลับไปอ่าน เกม: ครอบกล่องบทสนทนาให้พอดี มังงะ: เริ่มจากหนึ่งกรอบคำพูดหรือบริเวณเล็ก ๆ ก่อน
6. เมื่อข้อความเปลี่ยน แอปจะล้างคำแปลเก่า รอภาพนิ่งประมาณ 0.5 วินาที อ่านข้อความใหม่ แล้วแปลทับให้

| ปุ่มลัด | การทำงาน |
|---|---|
| Ctrl + Alt + R | เลือกพื้นที่ใหม่ และพักการแปล |
| Ctrl + Alt + T | เริ่ม / พักการแปล |
| Ctrl + Alt + F | แปลพื้นที่เดิมอีกครั้ง |
| Esc | ยกเลิกขณะเลือกพื้นที่ |

หน้าต่างคำแปลคลิกทะลุได้ จึงเลื่อนมังงะหรือคลิกเกมต่อได้ หากปุ่มลัดชนกับโปรแกรมอื่น ให้ใช้ปุ่มในหน้าควบคุมแทน

## โหมดเกม Type-Moon

- ครอบเฉพาะกล่องบทสนทนา หลีกเลี่ยงฉากหลังเคลื่อนไหว
- อ่านทั้งกล่องแล้วแปลรวมกัน เพื่อเก็บบริบทของประโยค
- แสดงพื้นหลังสีเข้มและคำแปลไทยทับกล่องเดิม
- ถ้าเกมค่อย ๆ พิมพ์ตัวอักษร ให้เพิ่ม “รอข้อความนิ่งก่อนแปล” เป็น 800–1,200 ms
- ไม่อ่านหน่วยความจำเกม ไม่ดัดแปลงเกม และไม่ใช้ text hook
- เกมที่ใช้หน้าจอเต็มแบบ exclusive อาจทำให้ overlay ไม่แสดง ให้เปลี่ยนเป็นหน้าต่างหรือไร้ขอบ

## โหมด MangaDex

อัปเดตการวางคำแปล: ไม่ขยายกล่องออกจากขอบข้อความที่ OCR ตรวจพบอีกแล้ว ใช้การตัดบรรทัดและลดขนาดตัวอักษรแทน เพื่อไม่ให้กล่องกว้างล้ำไปทับภาพด้านข้าง

ในหน้าตั้งค่าเลือก **พื้นหลังคำแปล** ได้เป็นสีพื้นเดิมอัตโนมัติ / ขาว / เข้ม / เลือกสีเอง และปรับ **ความทึบ** 0–100% ได้ทันที (0% ไม่มีพื้นหลัง แต่ข้อความเดิมจะยังเห็นอยู่) สีอัตโนมัติใช้สีที่พบมากในบริเวณข้อความ ไม่ใช่การวาดภาพด้านหลังกลับคืน

ตัวเลือก **กรองพื้นหลัง (อาจทำให้บางคำพูดหาย)** ปิดเป็นค่าเริ่มต้น เพื่อไม่ให้คำพูดถูกตัดออกเพราะพื้นหลังมีลายหรือแสงไม่สม่ำเสมอ เปิดได้เมื่อต้องการลดป้ายในฉากหลัง แต่เป็นเพียงการประมาณจากพื้นรอบข้อความ หากคำบรรยายหายไปให้ปิด รุ่นที่เปิดอยู่ต้องปิดแล้วเปิดใหม่ผ่าน Start.cmd เพื่อรับการปรับปรุง

สำหรับภาพใหญ่กว่า 1,800 พิกเซล โปรแกรมอ่านเป็นส่วนที่ซ้อนกันแล้วตัดข้อความซ้ำออก ช่วยลดการตกหล่นจากการย่อทั้งหน้าลงเล็ก ๆ และแยกตัวอักษรเอฟเฟกต์ขนาดใหญ่ออกจากบรรทัดบทสนทนา การอ่านภาพใหญ่จะใช้เวลามากขึ้นตามจำนวนส่วน

- เปิดมังงะตามปกติ ไม่ต้องให้แอปเข้าสู่ระบบ MangaDex
- เลือกพื้นที่ภาพมังงะบนจอ แอปทำงานจากภาพที่เห็น ไม่ดาวน์โหลดบทหรือแก้ไฟล์ต้นฉบับ
- จัดกลุ่มบรรทัดใกล้กัน วาดพื้นสีอ่อนและคำแปลทับบริเวณข้อความ
- มีการจัดลำดับญี่ปุ่นแนวตั้งจากขวาไปซ้าย และจัดตัวอักษรแนวตั้งใหม่สำหรับ OCR
- เมื่อเลื่อนหน้า แอปจะซ่อนคำแปลเก่าและแปลใหม่หลังภาพนิ่ง
- การอ่านหลายกรอบพร้อมกันยังอาจรวมกรอบผิด โดยเฉพาะคำพูดติดกัน ฟุริงานะ ตัวอักษรเอียง และตัวหนังสือบนภาพวาด เลือกทีละกรอบและซูมเข้าเพื่อเพิ่มความแม่นยำ

## ขอบเขตและความเร็ว

นี่เป็น **รุ่นทดลองที่ทำงานได้** ยังไม่ได้ตรวจบนเกม Type-Moon ของผู้ใช้หรือหน้ามังงะจริงของผู้ใช้

- ทดสอบจริงบนเครื่อง RTX 5050 8 GB / RAM 16 GB ด้วยภาพตัวอย่างอังกฤษ ญี่ปุ่นแนวนอน และญี่ปุ่นแนวตั้ง
- ตัวอย่างสั้นหลังโมเดลพร้อมใช้เวลารวม OCR + แปลประมาณ **0.7–1.7 วินาที**; ทดสอบจับภาพสดสองประโยคใช้ **1.3 วินาที** ต่อประโยค ไม่รวมรอภาพนิ่งและช่วงตรวจภาพประมาณ 0.2 วินาที
- การโหลดโมเดลครั้งแรก บทสนทนายาว หรือเกมใช้การ์ดจอมาก จะช้ากว่านี้ จึงไม่ใช่การแปลทันทีทุกเฟรม
- โมเดลเล็กอาจแปลไทยแข็งหรือคลาดเคลื่อน โดยเฉพาะศัพท์เฉพาะ เนื้อเรื่อง และคำกำกวม ตรวจข้อความต้นฉบับกับคำแปลในหน้าควบคุมได้
- การแปลทับใช้กล่องสีปิดข้อความเดิม ไม่ใช่การลบอักษรและวาดภาพด้านหลังคืนแบบ inpainting
- รองรับพื้นที่คงที่บน **จอหลัก** ในรุ่นนี้ หากย้ายหน้าต่าง ปรับความละเอียด หรือเปลี่ยน DPI ให้เลือกพื้นที่ใหม่
- ตัวอักษรจะลดขนาดเพื่อให้พอดีกรอบ หากกรอบเล็กมาก คำแปลอาจอ่านยากหรือล้นจนถูกตัด ให้ซูมภาพ/เลือกบริเวณใหญ่ขึ้น และอ่านข้อความเต็มในหน้าควบคุม

## เลือกโมเดลและจัดการข้อความที่ขาด

ช่อง **โมเดลแปลภาษา** แสดงโมเดลที่ติดตั้งในตัวรันของ MoonTranslate (`127.0.0.1:11439`) กดรีเฟรชรายชื่อได้ ใช้ `qwen3:4b-instruct` เป็นค่าเริ่มต้น การเปลี่ยนโมเดลมีผลกับรอบแปลถัดไป และอาจรอโหลดโมเดลใหม่ รายชื่อนี้ไม่รวมโมเดลจาก Ollama ตัวอื่น/พอร์ตอื่น และไม่ได้ดาวน์โหลดโมเดลใหม่ให้เอง ความสามารถในการแปลและความเร็วขึ้นอยู่กับแต่ละโมเดล

ช่อง **คำไม่ครบ เช่น Big si…** มีสองตัวเลือก:

- **แปลคำขาดเท่าที่เข้าใจ และคง …**: อนุญาตให้อนุมานเมื่อมีความหมายที่ชัดพอ และคงคำแปลให้ขาด เช่น `Big si...` → `พี่สา…` ถ้าอ่านไม่ออกหรือกำกวมมากให้ข้าม ผลอนุมานยังอาจผิดได้
- **ข้ามข้อความที่ขาด / ลงท้าย …**: ข้ามทั้งกลุ่มข้อความที่ลงท้ายด้วยจุดหลายจุด `…` หรือขีด รวมถึงประโยคสมบูรณ์ที่ลงท้ายแบบนี้ด้วย เป็นการเลือกอย่างระมัดระวัง ไม่ใช่พจนานุกรมตรวจคำทุกภาษา

ข้อความที่ข้ามจะไม่มีกล่องคำแปลปิดทับ เมื่อข้อความต้นฉบับปรากฏครบ โปรแกรมจะอ่านใหม่ตามปกติ การเปลี่ยนตัวเลือกจะยกเลิกผลเก่าและแปลรอบใหม่ แคชแยกตามโมเดลและวิธีจัดการคำขาด ทั้งสองตัวเลือกถูกบันทึกไว้เมื่อปิดแอป

## คำศัพท์เฉพาะและชื่อตัวละคร

กด **เปิดคำศัพท์เฉพาะ / ชื่อตัวละคร** แล้วแก้ไฟล์ `glossary.json` เป็นคู่ต้นฉบับกับคำแปลที่คุณต้องการ เช่น

```json
{
  "Saber": "เซเบอร์",
  "セイバー": "เซเบอร์"
}
```

บันทึกไฟล์แล้วกด **แปลใหม่** คำศัพท์ส่งให้โมเดลเป็นแนวทาง จึงยังอาจไม่ตรงทุกครั้ง

## การทำงานในเครื่อง

หลังดาวน์โหลดส่วนประกอบครบ OCR และการแปลทำงานออฟไลน์ ข้อความส่งเฉพาะตัวรันบน `127.0.0.1:11439` และไม่ใช้บริการแปลบนคลาวด์ แอปไม่บันทึกภาพหน้าจอ ประวัติคำแปลและแคชอยู่ในหน่วยความจำและหายเมื่อปิดแอป

Ollama ที่ติดตั้งสำหรับแอปแยกจากพอร์ตมาตรฐาน โมเดลจะค้างในหน่วยความจำได้ประมาณ 5 นาทีหลังใช้งานครั้งล่าสุด แล้วคืนหน่วยความจำโดยตัวรันเบื้องหลังยังทำงานอยู่

ข้อมูลแอปปกติอยู่ใน `%LOCALAPPDATA%\MoonTranslate` สำหรับการติดตั้งจาก Codex บนเครื่องนี้ Windows จัดเก็บจริงใน `%LOCALAPPDATA%\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\MoonTranslate` ไฟล์ `Start.cmd` ตรวจทั้งสองตำแหน่งให้แล้ว

## หากมีปัญหา

รุ่นปรับงานหลายกลุ่ม: เตรียม LaMa ล่วงหน้าพร้อมโมเดลแปล และเติมภาพบน CPU พร้อมแปลบน GPU ใช้ตัวตรวจข้อความ PP-OCRv5 mobile เป็นค่าเริ่มต้น รอบทดสอบ 8 กลุ่มพื้นเรียบเสร็จครบ 3.21 วินาที; 8 กลุ่มผสมภาพลายซับซ้อน 2 ช่องเสร็จครบ 4.78 วินาที หลังเตรียมระบบแล้ว ไม่รวมเวลาเปิดเตรียมครั้งแรก ผลกับหน้าอื่นขึ้นกับขนาดและความซับซ้อนของภาพ ดูบรรทัด PERFORMANCE ใน `%TEMP%/MoonTranslate-startup.log` เพื่อแยกคอขวดของภาพที่ใช้งานจริง

โหลด OCR/โมเดลแปลล่วงหน้าเมื่อเปิดแอปหรือเปลี่ยนโมเดล/ภาษา รอข้อความ “โมเดลพร้อมแล้ว” ก่อนเริ่มแปล และจำภาษาที่เลือกไว้เมื่อปิดโปรแกรม การทดสอบภาพบทสนทนาล่าสุดหลังเตรียม Gemma แล้วใช้เวลาประมวลผล 1.05–1.31 วินาที (ไม่ใช้แคช) เมื่อเผื่อรอบจับภาพและรอภาพนิ่ง 0.7 วินาทีเป็นประมาณ 1.75–2.01 วินาที ตัวเลขนี้ไม่รวมเตรียมโมเดล และไม่รับประกันกับหน้าเต็ม/ภาพที่ต้องเติมพื้นหลังด้วย LaMa

มังงะต้องตั้งหน้ากระดาษตรง: ปิดการหมุนข้อความ 180 องศาอัตโนมัติในโหมดมังงะแล้ว เนื่องจากตัวเอียงบางแบบถูกหมุนผิดและอ่านกลับหัว มีแคชภาพอ่าน/พื้นหลังสูงสุด 12 ภาพหรือ 32 MiB สำหรับภาพเดิมที่กลับมาอ่านซ้ำหรือสลับโมเดล ภาพที่เปลี่ยนแม้เพียงพิกเซลเดียวจะอ่านใหม่

### รอบปรับคุณภาพมังงะ 18 กันยายน 2026

- พื้นหลังลายซับซ้อนใช้ LaMa Manga ONNX ในเครื่อง (207 MB) พร้อม mask ที่ครอบขอบขาวของตัวอักษร ตรวจ SHA256 ตอนติดตั้งและแก้เฉพาะพิกเซลที่อยู่ใน mask บอลลูนพื้นเรียบยังใช้ OpenCV เพื่อประหยัดเวลา
- เลือกภาษา “อังกฤษ” เพื่อใช้ OCR อังกฤษเฉพาะทาง; “อัตโนมัติ” และ “ญี่ปุ่น” ยังใช้รุ่นหลายภาษา
- อ่าน OCR ซ้ำเฉพาะบรรทัดคะแนนต่ำ/ตัวพิมพ์ผิดปกติ สูงสุด 6 บรรทัดต่อภาพ และแทนผลเมื่อมีหลักฐานเพิ่ม คำเอียงเล็กยังอาจอ่านผิดได้
- คำแปลใช้ภาษาพูดไทยมากขึ้นและตรวจทานเฉพาะผลที่เติมคำถามเอง ไม่ตรวจซ้ำทั้งหน้า ประโยคซ้ำแปลครั้งเดียวแต่แสดงครบทุกตำแหน่ง ส่วน API สำหรับการทดลองยังรองรับการตรวจทั้งชุดด้วย `review=True`
- โมเดลเติมภาพมาจาก https://huggingface.co/mayocream/lama-manga-onnx (Apache-2.0 ตาม model card), อ้างอิงโมเดล https://huggingface.co/dreMaz/AnimeMangaInpainting ต้องมีไฟล์ในโฟลเดอร์ข้อมูลแอป `inpainting/lama-manga.onnx`; หากไม่มีจะใช้ OpenCV แทน รัน `prepare_inpainting.py` หรือ Setup.cmd เพื่อติดตั้ง
- ภาพที่เติมเป็นการคาดเดาพื้นหลัง ไม่ใช่การกู้เส้นต้นฉบับอย่างแน่นอน และ OCR ตัวเอียงเล็กยังผิดได้

มังงะจะไม่ใช้ตัวกรองพื้นหลังสีเรียบอีกต่อไป เพื่อให้ข้อความขอบขาวบนลายภาพและกล่องบรรยายถูกส่งแปลด้วย การจัดบรรทัดใช้ PyThaiNLP แบบ local เพื่อรักษาคำไทยไว้ด้วยกัน ลดขนาดฟอนต์ตามความกว้างและความสูงจริงของช่อง และจัดความยาวบรรทัดให้สมดุล เมื่อเห็นขอบบอลลูนปิดครบจะวางข้อความกลางพื้นที่ปลอดภัย ไม่บังคับจำนวนบรรทัดตามภาษาอังกฤษ การเติมภาพใช้บริบทใกล้พื้นที่ลบเพื่อลดการสร้างรอยคำจากช่องข้างเคียงกลับมา แต่ยังอาจมีรอยเติมภาพหรือข้อความที่ OCR อ่านไม่ครบ

### เร่งการเติมพื้นหลังด้วยการ์ดจอ

รุ่นนี้ใช้ LaMa ผ่าน DirectML อัตโนมัติเมื่อมีตัวเร่งติดตั้งไว้แล้ว (เครื่องนี้ติดตั้งให้แล้ว) เปิดใหม่ผ่าน `Start.cmd` เพื่อใช้รุ่นล่าสุด รอข้อความโมเดลพร้อมก่อนเริ่ม การโหลดครั้งแรกยังใช้เวลาประมาณ 10–11 วินาทีในชุดทดสอบ ส่วนการประมวลผลครบ 8 ช่องพื้นหลังซับซ้อนผ่าน Worker ใช้ 5.203 วินาทีหลังเตรียมเสร็จ เป็นชุดภาพจัดวางเพื่อทดสอบ ไม่รับประกันเวลาทุกหน้า

ตัวเร่งใช้โมเดลและความละเอียดเดิม แยกจาก runtime ของ OCR ถ้า GPU ใช้ไม่ได้จะกลับ CPU และอาจช้าลง ดูบรรทัด `INPAINT_BACKEND` ใน `%TEMP%/MoonTranslate-startup.log` เพื่อตรวจว่าใช้ GPU หรือ CPU สำหรับเครื่องใหม่ `Setup.cmd` จะติดตั้งตัวเร่งเป็นส่วนเสริมด้วย

### ส่งภาพเข้า OBS

กด “เปิดหน้าต่างภาพแปลสำหรับ OBS” แล้วเพิ่ม Source แบบ Window Capture ใน OBS เลือกหน้าต่าง `MoonTranslate OBS` หน้าต่างนี้รวมภาพพื้นที่ที่เลือกกับคำแปล และอัปเดตเมื่อภาพนิ่ง/แปลเสร็จ ไม่ใช่วิดีโอหน้าจอ 60 fps ขณะเลื่อนเปลี่ยนหน้า หน้าต่างจะแสดงรอภาพเพื่อไม่แสดงคำแปลเก่าผิดหน้า วางหน้าต่างนี้และหน้าพรีวิว OBS นอกพื้นที่ที่เลือกอ่าน OCR (หรือบนจอที่สอง) และอย่าย่อหน้าต่าง ปิดหน้าต่างนี้ได้โดยไม่หยุดการแปล

Overlay บนหน้าจอหลักยังซ่อนจาก Display Capture เพื่อป้องกัน OCR อ่านคำแปลซ้ำ ให้ใช้ Window Capture ของหน้าต่างส่งภาพนี้เมื่อต้องการบันทึกคำแปล

โหมดเริ่มต้นเป็นมังงะแล้ว การลบข้อความจำกัดตามรูปหลายเหลี่ยมของ OCR และเก็บภาพพื้นหลังจริงไว้นอกบริเวณลบ ถ้าพบบอลลูนสีเรียบปิดชัดเจน โปรแกรมจะขยายพื้นที่จัดข้อความด้านในโดยเว้นขอบและหลบข้อความกลุ่มอื่น ถ้าบอลลูนเปิด/ถูกตัดขอบภาพหรือพื้นหลังซับซ้อน จะใช้กรอบข้อความเดิมเพื่อเลี่ยงการทับเส้นภาพ ยังไม่ใช่การตรวจบอลลูนด้วยโมเดล segmentation และยังอาจมีข้อความที่ OCR อ่านตกหล่น

คำแปลใช้ข้อความใกล้เคียงในภาพปัจจุบันเป็นบริบทเพื่อรักษาชื่อและสรรพนาม โดยไม่เก็บบริบทข้ามหน้าอัตโนมัติ แคชแยกตามบริบทด้วย การอ่านข้อความละเอียดขึ้นอาจใช้เวลาเพิ่ม จึงแนะนำเลือกเฉพาะส่วนของหน้าที่กำลังอ่าน

เลือก `gemma-4-E4B-it (local GGUF)` ในช่องโมเดลแปลภาษาได้แล้ว โปรแกรมใช้ไฟล์เดิมใน `C:/local-game-subs/models/gemma-4-E4B-it-Q4_K_M.gguf` และตัวรัน `C:/local-game-subs/llama.cpp/vulkan/llama-server.exe` โดยไม่ดาวน์โหลดหรือคัดลอกโมเดล ใช้ OCR เดิมแล้วส่งข้อความให้ Gemma แปล ไม่โหลดตัวอ่านภาพ mmproj หากย้ายหรือลบไฟล์เหล่านี้ ตัวเลือก Gemma จะหายไปหลังรีเฟรชรายชื่อ

Gemma โหลดเมื่อเริ่มแปลครั้งแรกและอาจใช้เวลาสักครู่ ตัวรันรับการเชื่อมต่อเฉพาะเครื่องนี้ โปรแกรมปล่อยโมเดลจาก Ollama ของ MoonTranslate ก่อนโหลด Gemma และปิดตัวรัน Gemma เมื่อเริ่มงานแปลด้วย Qwen หรือปิดโปรแกรม ตรวจข้อผิดพลาดได้ที่ `gemma-engine.log` ในโฟลเดอร์ข้อมูลแอป

- เปิดไม่ได้: ตรวจว่ามีโฟลเดอร์ runtime ที่ติดตั้งไว้ เปิด `Start.cmd` ไม่ใช่ดับเบิลคลิกไฟล์ `.py`
- ขึ้นว่าโมเดลไม่พร้อม: ตรวจ `engine.log` ในโฟลเดอร์ข้อมูลแอป หรือเปิด `Setup.cmd` เพื่อติดตั้งส่วนประกอบใหม่ (ต้องต่ออินเทอร์เน็ต)
- OCR ผิด: ซูมข้อความ เลือกพื้นที่ให้เล็กลง และเลือกภาษาให้ตรง
- ไม่ยอมแปล: พื้นที่ที่เลือกอาจมีภาพเคลื่อนไหวตลอดเวลา เลือกเฉพาะบทสนทนา/กรอบคำพูด
- คำแปลค้าง/แปลไม่สำเร็จ: กด Ctrl+Alt+F หรือพักแล้วเริ่มใหม่
- ภาพ overlay ไม่แสดง: ใช้เกมโหมดหน้าต่าง/ไร้ขอบ และตรวจว่าเลือก “แสดงคำแปลทับ”
- เกมกระตุก: ปิดโปรแกรมที่ใช้การ์ดจอ เลือกพื้นที่แปลเล็กลง หรือลดคุณภาพกราฟิกเกม

## โครงสร้างสำหรับพัฒนาต่อ

- `app.py`: หน้าควบคุมภาษาไทย การเลือกพื้นที่ การตรวจภาพเปลี่ยน overlay และปุ่มลัด
- `core.py`: OCR จัดกลุ่มข้อความ อ่านแนวตั้ง และแปลผ่านโมเดลในเครื่อง
- `prepare_engine.py`: ดาวน์โหลดและตรวจ checksum ตัวรันอย่างเป็นทางการ พร้อมดาวน์โหลดโมเดล
- `requirements.txt`: เวอร์ชันไลบรารีที่ทดสอบแล้ว
- `Setup.cmd`: เตรียม Python และส่วนประกอบ โดยใช้ uv ที่มีอยู่บนเครื่อง
- `Start.cmd`: เปิดแอป
- `test_core.py`: ทดสอบการตรวจภาพ การจัดกลุ่มข้อความ การยกเลิกงาน และแคช; เพิ่ม `--integration` เพื่อทดสอบ OCR และแปลจริงด้วยภาพที่สร้างขึ้น

โปรแกรมอาศัย [RapidOCR](https://github.com/RapidAI/RapidOCR), [Qt/PySide6](https://doc.qt.io/qtforpython-6/), [Ollama](https://docs.ollama.com/windows) และ [Qwen3 4B Instruct](https://ollama.com/library/qwen3:4b-instruct) โมเดลและไลบรารียังคงใช้เงื่อนไขใบอนุญาตของเจ้าของแต่ละโครงการ
